# stash clean-up — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task by task. On the Mac,
> Python is written by the `python-development` orchestrator or writers (CLAUDE.md), under owner
> ruling R15. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Make stash cheaper to change by:
- running every test on the one real store;
- deleting redundant unit tests, checked against branch coverage;
- collapsing the fakes;
- replacing layered concurrency with one write lock;
- keeping Protocols only at real seams;
- shrinking the owner docs.

All of this happens with no owner-visible behaviour change.

**Architecture:** Six steps in order. Each step is one task, or a few sub-tasks, and each ends
green with its own commit. Coverage is measured before and after every task, and the coverage of
the `src` that remains must not drop.

**Tech Stack:** unchanged, plus `pytest-cov` (dev group only).

**Spec:** `docs/superpowers/specs/2026-11-07-cleanup-design.md`. Read its "Settled after the
builder check" section: those calls are binding.

## Global Constraints

- **No owner-visible behaviour change.** The one exception: the race-only "That changed
  meanwhile — try again" reply goes. Domain checks keep their replies (the main one: a "Didn't
  happen" press whose date no longer matches the item).
- **The gate.** `make check` stays the only gate and is green before every commit. On the Mac,
  the 4 real-socket tests and tesseract skip. Target ≤ 30 s wall-clock (today ~20 s).
- **Coverage, per task.** Line and branch coverage of the `src` that remains must be at or above
  the same code's coverage just before the task. A unit test may be deleted only if its branches
  stay covered by acceptance, contract and integration tests alone, and a reviewer confirms the
  behaviour is asserted there.
- **Coverage and behaviour beat the size targets.** Report the numbers reached. Targets:
  - tests ≤ ~25k lines;
  - fake files ≤ ~25;
  - `class …(Protocol)` in `src` ≤ ~30 (81 today);
  - `docs/usage.md` ≤ ~200 lines.
- **These tests must survive in some form** (anti-goals):
  - stale "Didn't happen";
  - no proposals for past dates;
  - withdraw on a failed proposal send;
  - people backlinks on add, rename or alias;
  - a repeated key date corrects;
  - a press on a batched nudge answers in a new message;
  - confirmed steps block reroute;
  - only the closest key-date lead fires;
  - first-run seeding;
  - RF1 XSS payloads;
  - the token 404 / compare / log rules;
  - Hermes fake fidelity (refused inject, factory dedupe, `spawn_task` outside a loop);
  - PTB kwargs bound to the installed PTB 22.8.
- **Unchanged:** migrations, schema, runtime dependencies, the Hermes pin and spike-m0 rows. No
  features. Fake data only. Offline only.
- **R15:**
  - one critique round, ≤ 3 reviewers;
  - sonnet by default;
  - the orchestrator delegates its reading;
  - Minor findings go to the branch notes;
  - fix rounds go to a fresh writer;
  - no git commands in agents (the main loop commits).

## Review Focus

1. **The write lock held across an LLM or network call.** If a button press arrives while filing
   waits on the model (up to ~100 s), the press must answer without waiting for the filing. Pinned
   in Task 3.
2. **A ticker delivery and an owner press touching the same item.** A Done press while the ticker
   records that item's follow-up must not lose either write. Pinned in Task 3.
3. **SQLite `:memory:` is one database per connection.** A test that needs two connections (WAL,
   the serve snapshot, the busy store) must use a temporary file. On `:memory:` it would pass
   against two separate empty databases. Pinned in Task 1.
4. **A deleted unit test that was the only assertion of a review fix.** It must fail the
   anti-goal list check. Pinned in every Task 2 sub-task.
5. **Collapsing a fake that guards a live-service fact.** The Hermes ctx and PTB fakes stay
   behaviourally strict. Pinned in Task 4.

### Task 1: Coverage target and one store in tests

- Modify: `pyproject.toml` (dev: `pytest-cov`), `uv.lock` (`.venv/bin/uv lock --default-index https://pypi.org/simple`), `Makefile`.
- Modify: `tests/fakes/store_factories.py` and every test that uses `MemoryStore` or `memory_store` (about 156 files).
- Delete: `tests/fakes/memory_store.py`, `memory_item_writes.py`, `memory_ledger.py`, `memory_people.py`, `memory_queries.py`, `memory_steps.py`, `in_memory_connection.py` (if only the memory family uses it).

**Interfaces:**
- Produces two targets:
  - `make coverage`: the default and `-m integration` runs with `--cov=stash --cov-branch`, appended into one data file. It prints the total and writes `coverage.json`.
  - `make coverage-without-unit`: the same, but runs only `tests/acceptance tests/contract tests/integration`.

  Neither is part of `make check`.
- Produces `tests/fakes/store_factories.py::sqlite_store()`: the one store factory, a real
  `SqliteStore`. Use `:memory:` if `SqliteStore` can take it without changing `src`; otherwise use
  a temporary file. Keep `two_connections(directory)` for multi-connection tests.
- Contract tests lose the store parametrisation and run once, on SQLite.

- [ ] **Step 3:** Replace every `MemoryStore` and `memory_store` use with `sqlite_store()` (or a

### Task 2: Delete redundant unit tests (coverage-guided)

Split into three sub-tasks, one commit each, in this order:
- **2a:** `tests/unit/{capture,hermes_adapter,cli}`.
- **2b:** `tests/unit/{store,lifecycle,planning,nudges,people,delivery,suggestions}`.
- **2c:** everything else under `tests/unit`, including the architecture tests: merge them into the shared guard tables where they repeat it.

**Interfaces:** consumes Task 1's two coverage targets. Produces no new code.

For each sub-task:
- [ ] **Step 1:** Run `make coverage` and `make coverage-without-unit`. Save the per-file branch
  coverage as this sub-task's baseline.
- [ ] **Step 2:** For each unit test file in scope, decide one of:
  - **delete:** its branches are covered by `coverage-without-unit` and asserted at that tier;
  - **trim:** keep only the cases that are the sole cover of a branch;
  - **merge into a parametrised table:** typical for config and validation;
  - **keep:** it falls in a design goal-2 keep category (date/DST/Feb 29, escaping/URL schemes,
    hostile LLM or link output, wire formats, config tables).

  Record each decision in a table in the task report: file, decision, lines before and after.
- [ ] **Step 3:** Check every item of the Global Constraints survive list. Each one must still
  have a test; name it in the report.
- [ ] **Step 4:** `make check` is green. `make coverage` is at or above the Step 1 baseline for
  every `src` file.
- [ ] **Step 5: Commit** `test: drop unit tests already pinned at acceptance/contract level (<packages>)`.

### Task 3: One write lock for the gateway process

**Files:**
- Modify: `src/stash/app/build.py` (build one lock), `src/stash/lifecycle/{service,_guards,errors,__init__}.py`, `src/stash/capture/{fixes,completion_buttons,replies,callback_log}.py`, `src/stash/planning/service.py`, `src/stash/delivery/*` or `src/stash/hermes_adapter/ticker.py` (the ticker delivery), `src/stash/store/{port,sqlite,_item_writes,__init__}.py`.
- Delete: `docs/store-writes.md` (its content returns in Task 6 only where an owner needs it), `tests/fakes/{racing_item_store,changing_item_store,overlap_waiting_lifecycle}.py` and the race tests (`tests/unit/lifecycle/test_concurrent_changes.py`, `test_grouping_races.py`, `tests/unit/capture/test_fixes_concurrent_changes.py`, and their contract counterparts).

**Interfaces:**
- Produces one write lock, built in `stash.app`. It is a `threading.Lock`, or a small named
  context manager, `OwnerWrites`. It is passed to every component that does an item
  read-modify-write and to the ticker's delivery. It is held around store sections only.
- Removed:
  - the `update_item(..., replacing=)` and `record_completion(..., replacing=)` keyword;
  - `StaleItemError`;
  - `ItemChanged` where it signals a race;
  - the per-service locks in `capture/fixes.py:47` and `planning/service.py:54`.
- Store writes become a plain update. A missing row still raises `UnknownItemError`.
- Kept:
  - the domain stale-button check in `Lifecycle.didnt_happen` (a renamed exception, such as
    `StaleButton`, is allowed) and its reply;
  - `SerializedPipeline` (`capture/serial.py`);
  - the store `RLock` (connection safety);
  - `BEGIN IMMEDIATE` and `StoreBusyError`;
  - atomic `group_item`;
  - `record_all_sent`;
  - the double-tap window;
  - the ticker's no-overlap guarantee.

- [ ] **Step 1: Failing tests:**
  - `tests/acceptance/test_owner_writes.py::test_a_button_press_answers_while_filing_waits_on_the_model`
    (Review Focus 1): a gated chat model blocks filing, a Done press on another item answers, and
    then the model is released.
  - `…::test_a_done_press_and_a_ticker_follow_up_on_the_same_item_both_land` (Review Focus 2):
    the item is DONE and the follow-up is recorded sent.
- [ ] **Step 2:** Implement the lock and remove the machinery listed above. Update any test that
  expected "That changed meanwhile".
- [ ] **Step 3:** `make check` green; `make coverage` at or above the pre-task baseline for the
  remaining `src`.
- [ ] **Step 4: Commit** `refactor: one process write lock replaces conditional writes and per-service locks`.

### Task 4: One fault-injecting store wrapper

**Files:**
- Create: `tests/fakes/faulty_store.py`.
- Modify and delete: the single-fault store fakes. These are `busy_store`, `failing_*_store`
  (completion, delete, link, list, read, save, search, status), `vanishing_item_store`,
  `lingering_step_store`, `watched_step_store`, `snapshot_watching_store`,
  `outcome_querying_store`, `outcome_save_counting_store`, `ledger_recording_store` and
  `thread_noting_store`.
- Keep: the Hermes ctx and PTB fakes, `chat_model` and its scripted variants, link inspection,
  GPU, OCR, the clocks, and any fake of a non-store external seam.

**Interfaces:**
- Produces `FaultyStore(real: SqliteStore, *, fail_on: Mapping[str, BaseException] = {}, record: bool = False)`,
  or an equivalent the builder picks.
  - **Behaviour:** a named store method raises the given exception, and everything else delegates
    to the real store.
  - **Recording (optional):** it records method calls, for tests that assert a read did or did not
    happen.
  - **Typing:** it type-checks under `mypy --strict tests/fakes` as a `Store`.
- [ ] **Step 1: Failing test:** `tests/unit/test_faulty_store.py`:
  - a configured method raises;
  - an unconfigured method returns the real store's result;
  - recorded calls list the method names in order.
- [ ] **Step 2:** Implement it, then move each single-fault fake's tests onto it and delete the
  fake. Review Focus 5: the Hermes ctx and PTB fakes and their own tests are not touched.
- [ ] **Step 3:** `make check` green, and coverage at or above the pre-task baseline.
- [ ] **Step 4: Commit** `test: one fault-injecting store wrapper replaces single-fault store fakes`.

### Task 5: Protocols only at real seams

**Files:** `src/stash/{capture,planning,suggestions,nudges,people,lifecycle,delivery}/ports.py`
and the matching code; `src/stash/hermes_adapter/{ports,ticker,outbox,events,assistant,telegram_io}.py`;
`src/stash/cli/commands.py`; and the architecture tests if a port module disappears.

**Interfaces:**
- **What counts as a real seam:** two implementations in `src`, or an external system behind it,
  or a fake that guards a live-service fact.
- **What stays:**
  - the store port (`stash.store.port`);
  - the LLM port (`stash.llm.port`);
  - the Telegram, Hermes ctx and outbox ports;
  - enrichment (link inspection, OCR);
  - the GPU probe;
  - clock and ids as callables.
- **What changes:** every other consumer-side Protocol becomes the concrete class, or the store
  port.
- **Duplicates to remove:** `PeopleRoster` (in both `hermes_adapter/ports.py` and
  `cli/commands.py`), and `NudgeDeliveries` vs `TickDelivery`.
- **Layering:** the architecture tests still pass. A layer rule that a Protocol existed to satisfy
  is met by importing the concrete type from the allowed package.
- [ ] **Step 1:** List every `class …(Protocol)` in `src` (81) in the task report, each marked
  keep or remove with its reason.
- [ ] **Step 2:** Remove the marked ones. `make check` green, and coverage at or above the
  pre-task baseline.
